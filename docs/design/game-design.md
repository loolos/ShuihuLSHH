# 重制版设计方案（game-design）

> 状态：**第一版完整草案**，2026-11-11。
> 原则（见 [project-overview.md](../project-overview.md)）：**关卡与剧情尽量还原，整体玩法尽量还原；具体数值、公式和 AI 可以重新设计**。
> 标记约定：
> - 【原版】：有文件证据的原版做法，附出处。
> - 【新设计】：本方案自行设计，原版做法未知或刻意改动。
> - 【待定】：需要负责人拍板，汇总在 §15，每项都附推荐。
>
> 数据来源见 [data-tables.md](data-tables.md)、[stage-briefs.md](stage-briefs.md)、[script.md](script.md)。

---

## 0. 一页概览

- **类型**：单人、剧情驱动、等距视角的回合制战棋 RPG，浏览器运行，画面随窗口自适应。
- **流程**：主角武龍从护送王進母子开始，一路结识好汉，最终上梁山。共 76 项关卡表：63 关，其中 32 关有胜负条件的战斗，31 关是剧情或训练；分 14–15 章。【原版】
- **队伍**：从 2 人逐步扩充到 16 人。**每关全员出场，没有出场选择**，这是原版做法（证据见 §1.3）。
- **战斗**：菱形格地图，单位有 4 个朝向。我方回合内逐个行动（移动 → 攻击、技能、道具或待机），然后友军、敌方依次行动。
- **成长**：经验升级（上限 30 级），每人按等级习得专属技能，"古武術祕笈"可领悟隐藏技；7 个装备栏，装备可强化。
- **还原重点**：每关的地图、敌我配置、对白、胜负条件、多种失败结局旁白，以及好汉加入的时机。
- **重新设计**：伤害、命中、成长公式，技能数值，敌方 AI，经济数值，UI，便利功能。

## 1. 游戏结构

### 1.1 关卡类型【原版，中】

| 类型 | 原版 | 数量 | 特征 | 重制版呈现 |
|---|---|---|---|---|
| 战斗 | `N*`、`N-add*` | 32 | 有回合限制、胜利条件和多条失败条件 | 完整战斗 |
| 剧情 | `Act*` | 29 | 没有胜负条件；多为 18×18 的室内小图，单位以 NPC 为主 | **在地图上演出的过场**：单位走位、对白，可跳过 |
| 训练 | `Train1/2` | 2 | "訓練回合數 --- 25"，对白是喝彩 | 可选的练习战，不影响主线 |

证据：在 [stage-briefs.md](stage-briefs.md) 中，带"勝利條件"字样的关卡全部是 `N*`/`N-add*`，`Act*` 一个都没有。少数 `Act*` 里有 1 个敌方单位，可能是过场中的对手（如 Act2-2 中主角与史進比武），需要游玩确认。

### 1.2 核心循环【新设计，依据原版结构】

```
章节标题卡 → 剧情过场（Act）→ 战前对白 → 战斗（N）→ 胜利旁白
   ↑                                           ↓
   └──────── 整备（装备、商店、强化、存档）←── 结算（经验、金钱、战利品）
```

- **整备界面**【新设计】：两场战斗之间可以换装备、买卖道具、强化装备、阅读兵书、存档。原版是否有商店、在哪里出现，目前不明。道具有买卖价、财宝说明写着"可典當"，所以有商店是确定的。
- **失败**：显示该失败条件对应的结局旁白（原版每关有 2–4 段，如 N01 的"王母在混戰之中被官兵所殺…"），然后回到战前。可选"从本回合重来"（新功能）。
- **存档**：整备界面可以手动存档；每关开始时自动存档；战斗中可以随时快速存档【新设计】。

### 1.3 队伍与出场【原版，中】

关卡数据里，每场战斗的我方单位恰好等于当时已加入的全部好汉：N01 2 人 → N03 6 人 → N08 8 人 → N11 11 人 → N-add14 起 16 人。没有看到"可选出场"的痕迹。

- **重制版沿用"全员出场"**。原版每关为每个好汉指定了初始坐标，直接用这些坐标即可。
- 好汉在 ACT 里的等级大多写成 1，推测是"沿用存档中的等级"的占位。新加入的好汉写着明确等级（林沖 10、魯智深 7、楊志 18、公孫勝 23…），推测是加入时的初始等级。
- **N-add14 是例外**：16 名好汉都有明确等级（武龍 30、晁蓋 23…），看起来是一段固定配置的剧情战（推测是智取生辰綱）。重制版对这种关卡使用固定队伍，不读存档。【低，待游玩确认】

### 1.4 好汉加入时机【原版，高】

## 2. 战场

### 2.1 地图与坐标【原版】

- 菱形等距格，每格画面尺寸 90×46；地图为 18×18、36×36、54×54，以及一张 36×54。
- 格子 (x, y) 的屏幕中心 = ((x − y) × 45, (x + y) × 23)。已用全部 63 张图验证，接缝连续。【中】
- 每格 1 层地表，加 0–4 层地上物（树、石、建筑件）。
- 绘制顺序：先画全部地表，再按 x + y 从远到近画地上物和单位。同一格内：地上物 → 单位 → 遮挡物。重制版需要处理"单位被树挡住"的半透明效果【新设计】。

### 2.2 通行与地形

- **通行**【原版，低】：`Ground.att` / `Upper.att` 为每个图块标记 0 或 0xFF，推测 0xFF = 不可通行。重制版以它为默认值，配合人工修正表 `overrides/passability.json`。
- **地形效果**【新设计】：原版没有找到地形表。重制版只做两档，保持简单：
  - **普通地面**：移动消耗 1，无修正。
  - **掩体**（草丛、树林边缘等，人工在图块上标注）：移动消耗 2，在其中被攻击时闪避 +10%。
  - 第一版可以只做"可走 / 不可走"，掩体留到平衡阶段再加。【待定 D-6】
- **单位阻挡**【新设计】：可以穿过友方，不能穿过敌方；**没有区域控制**（ZOC），降低上手难度。

### 2.3 朝向【原版存在；用法为新设计】

单位有 4 个朝向（ACT 朝向字段 0–3，`Man.lib` 每个动作有 4 方向）。重制版让朝向参与战斗：

- 行动结束后选择朝向（默认朝向最后的移动方向）。
- 从**侧面**攻击：命中 +10%；从**背后**攻击：命中 +20%，伤害 ×1.2。
- 这让站位有意义，而且原版本来就有朝向数据。【待定 D-3：如果想更简单，可以只做表现、不做加成】

### 2.4 回合结构【新设计】

- **阵营回合制**：我方全体 → 友军（AI 控制）→ 敌方，算一个回合。原版的回合顺序未知；阵营回合制是同类游戏最常见的做法，也和"限制回合數 50"这种计数方式相符。
- 我方每个单位每回合：**移动一次 + 一个行动**（攻击、技能、道具、待机），移动后仍可行动，行动后不能再移动。
- 新增便利功能：未行动前可以撤销移动；"全体待机"；敌方回合可快进。

## 4. 战斗计算【新设计】

目标：**数值透明、可以预判**。行动前显示命中率和预计伤害。公式里使用原版的属性名和量级，原版数据可以直接套用。

### 4.1 普通攻击

```
命中率   = clamp(70 + (攻方命中 − 守方敏捷) × 0.5 + 朝向修正 + 地形修正, 10, 99) %
A        = 攻方攻击 + 武器攻击加成
D        = 守方防御 + 衣服防御加成 + 头饰防御加成
伤害     = max(1, round(A² / (A + D) × 0.5 × 技能倍率 × 随机(0.9 – 1.1)))
必杀率   = clamp(攻方必杀 × 0.4, 0, 50) %       // 必杀 ×1.5 伤害
```

- 用比例式 `A²/(A+D)`，而不是减法 `A − D`：防御高时伤害递减但不会归零，低攻击单位对高防御目标也有效。原版装备加成从 +6 到 +50 跨度很大，减法公式容易出现"破不了防"。
- 以 N01 为例（数值见 data-tables 职业 0、32）：
  - 武龍（攻 65 + 皮手套 7 = 72）打士兵（防 20，生命 50）：约 28 点，两下打倒。
  - 士兵（攻 50）打武龍（防 30 + 官服 7 = 37）：约 14 点，武龍（生命 100）能挨 7 下。
  这符合第一关"以少打多但不能硬冲"的节奏。具体系数在平衡阶段调整。
- 装备加成取自道具说明中的"攻擊力加N / 防御力加N"（共 78 件武器、56 件防具），由工具解析出数值。原版数据区里没有找到这些数值，说明文字是唯一来源。【原版说明文字，高】

### 4.2 远程与反击

- **远程**：弓箭手等职业的普通攻击射程为 2–3 格（原版技能名表中有"遠程攻擊"类别）。
- **反击**【待定 D-2】：推荐**近战被攻击后，如果存活且攻击者在射程内，反击一次**（普通攻击，伤害 ×0.5）。这会让"谁先出手"更有策略，但也拖慢节奏。另一个选项是不反击，更接近简单的老式战棋。

### 4.3 状态异常【原版种类；效果为新设计】

| 状态 | 效果 | 持续 | 解除 |
|---|---|---|---|
| 中毒 | 每回合开始扣最大生命的 10% | 3 回合 | 解毒草藥、天山雪蓮 |
| 昏迷 | 跳过下一次行动 | 1 回合 | 解昏迷草藥、天山雪蓮 |
| 增益 | 由道具或技能给予，如"3 回合內攻擊力提升5點" | 按道具说明 | 到期 |

"抗毒""抗昏"道具使中毒、昏迷无效，持续数回合。

## 5. 成长

### 5.1 经验与升级【新设计】

- 每次行动获得经验：命中 10、击倒 30、治疗 10、技能命中另加 5；乘以等级差系数 `clamp(1 + (敌等级 − 己等级) × 0.1, 0.3, 2.0)`。
- 每 100 经验升 1 级，经验清零；上限 30 级（原版上限，来自 Editor 对 EXE 的分析【中】）。
- 敌方等级在 1–42 之间，随章节递增（见 stage-briefs 总览）。

### 5.2 属性成长【新设计，参考原版字母】

原版每项属性带一个等级字母（f、g、h、i、j、n）【原版，含义低置信度】。观察规律：防御和敏捷几乎全是 n，攻击、命中多为 h/i，王進的生命是 f，而他的初始生命最高（140）。推测**字母越靠前，成长越高**。

重制版把字母映射成每级成长期望值，实际成长按期望值随机取整，避免"升级白升"：

| 字母 | 生命/气力 每级 | 攻/防/命/敏/必 每级 |
|---|---|---|
| f | +12 | +4 |
| g | +10 | +3.5 |
| h | +8 | +3 |
| i | +7 | +2.5 |
| j | +6 | +2 |
| n | +4 | +1.5 |

这张表需要用"升级时的属性变化截图"校准（见 [README.md](README.md) §4）。

### 5.3 永久提升【原版】

- 兵书类：鬼谷子兵法 攻 +10、孫臏兵法 防 +10、孫子兵法 命 +10、黃石公兵法 敏 +10、孔明兵法 四项各 +5。阅读后消耗。
- **古武術祕笈**：领悟本角色当前等级可学的下一段隐藏技（LV1 → LV2 → LV3）。

## 6. 技能

### 6.1 结构【原版】

- 好汉各有 4–13 个专属技能（宋江没有技能），按等级 1–30 习得（见 data-tables §2）。
- 部分技能分级（千軍萬馬 LV1–3、天王托塔 LV1–5）：高级取代低级。
- 隐藏技（每人 3 段）需要古武術祕笈，同时要满足学习等级。
- 原版技能类型标签有 8 个：普通攻擊、遠程攻擊、防禦技、連續技、迴旋技、氣功技、集氣技、回復技。

### 6.2 重制版的技能模板【新设计】

每个技能落到下列模板之一，用数据表配置数值：

| 模板 | 对应原版类型 | 效果 | 举例 |
|---|---|---|---|
| 强击 | 普通攻擊 | 单体，伤害 ×1.3–2.0 | 一鳴驚人 |
| 远射 | 遠程攻擊 | 射程 2–4，单体 | — |
| 连击 | 連續技 | 单体连打 2–4 段，每段 ×0.6 | — |
| 回旋 | 迴旋技 | 以自身为中心，周围 1 圈 | 八面威風（推测） |
| 气功 | 氣功技 | 远距离范围攻击（菱形半径 1–3） | 五雷咒、千軍萬馬 |
| 集气 | 集氣技 | 本回合不攻击，下回合伤害 ×2 或回复气力 | — |
| 防御 | 防禦技 | 自身或邻接友军减伤 50%，持续 1 回合 | 一夫當關（推测） |
| 回复 | 回復技 | 回复生命，或解除状态 | 回心咒、回復計 |

### 6.3 数值基线【原版候选字段，低】

技能子项 58 B 中有几个字段的规律很像"消耗 / 范围 / 威力"：

| 字段 | 例：千軍萬馬 LV1 / LV2 / LV3 | 例：五雷咒 LV1 / LV2 / LV3 | 推测 |
|---|---|---|---|
| +8 | 25 / 45 / 60 | 40 / 50 / 70 | 气力消耗 |
| +16 | 3 / 5 / 7 | 2 / 3 / 4 | 范围 |
| +18 | 60 / 100 / 200 | 80 / 150 / 250 | 威力 |

基础招式（一鳴驚人、日月劍法）的 +8 是 0，符合"普通攻击不耗气"。**重制版直接用这三个字段作为初值**，再按模板换算。每个技能的类型（属于哪种模板）需要逐个确认：先用字段 +2/+3 自动猜，再人工过一遍。第一版只给第 1–2 章出场的 6 名好汉配齐技能。

### 6.4 特效

`Effect.lib` 有 60 组特效动画。技能与特效的对应还不知道（可能在技能子项尾部），先手工指定，每个模板一个默认特效。

## 7. 装备、道具与经济

### 7.1 装备栏【原版】

每人 7 栏：武器 1、衣服 1、头饰 1、物品 4。道具不可堆叠，同一道具每件占一栏。

### 7.2 武器限制【原版】

每个职业只能装备一类武器（11 类：手套/拳、棍、雙刀、大刀、槍、禪杖/鏟、刀、劍、雙劍、叉、槳）。

### 7.3 强化【原版有"可提升 / 無法提升"之分；机制为新设计】

- 200 件道具中，125 件说明写着"可提升"，9 件写着"無法提升"。
- 重制版：在整备界面花钱强化，每级 +10% 基础加成，最高 +5。费用 = 买价 × 等级 × 0.5。
- GOO +146 起的两段 1–13 序列可能是原版的升级路线，暂不采用。

### 7.4 消耗品【原版】

回复体力（狗皮膏藥 50 → 大還金丹 400）、回复气力（兔肉包子 50 → 人肉包子 全满）、同时回复、解毒、解昏迷、抗毒、抗昏、限时增益（藥酒、萬靈丹，3–5 回合）。效果按说明文字实现。

### 7.5 金钱【新设计，以原版价格为基准】

- **来源**：战斗胜利奖金（按关卡难度 300–3000）；地图宝物（ACT 中的"物件"单位，走到格子上拾取）；典当财宝（生辰綱等，卖价按原版）。
- **用途**：商店（原版买入价，卖出价为一半）；强化。
- **商店货品**：随章节解锁，大致按买价分档（第 1 章 ≤ 300，第 5 章 ≤ 1500…）【新设计】。

## 8. 敌方与友军 AI【新设计】

原版 ACT 的 w7 字段（0、1、256 … 2049，bit0 + 高字节 0–8）很可能编码了 AI 或出场条件，但还没解开。重制版定义一组行为模式，每个单位在关卡数据里指定一种；默认值按 w7 推测，再人工修正：

| 模式 | 行为 |
|---|---|
| 冲锋 | 朝最近的可攻击目标移动并攻击 |
| 固守 | 不移动；目标进入攻击范围才攻击 |
| 埋伏 | 先固守，有我方进入 N 格内或受到攻击后转为冲锋（N01 中 w7=512 的伏兵组可能就是这种） |
| 追击目标 | 优先攻击指定单位，如 N01 的官兵优先追王母 |
| 护卫 | 跟随指定单位，攻击靠近它的敌人 |
| 撤退 | 朝撤退区域移动（友军王母使用） |

**目标选择**：在可攻击目标中，按"能击倒 > 伤害最高 > 生命最低 > 最近"排序。敌方单位的出手顺序按敏捷从高到低。

难度选项【新设计】：简单（敌方属性 −15%、可多次撤销）/ 普通 / 困难（敌方属性 +15%、AI 会集火）。

## 9. 剧情与事件

### 9.1 内容还原【原版】

- 853 句对白和全部旁白、目标、结局文字，按原文使用（见 [script.md](script.md)）。

- `%X`、`%N` 替换为主角名（默认"武龍"，开局可改名【待定 D-5】）。

### 9.2 事件脚本格式【新设计】

原版 PAS 的事件指令还没解开，重制版用自己的事件脚本描述每关，人工编写，以剧本文本和游玩录像为准：

```jsonc
// stages/N01.events.json（示意）
{
  "objective": { "turnLimit": 50, "win": [{ "reach": { "unit": "王母", "area": "escape" } }],
                 "lose": [{ "dies": "王進", "ending": "lose_wangjin" }, { "dies": "王母", "ending": "lose_mother" },
                          { "dies": "$hero", "ending": "lose_hero" }, { "turnLimit": true, "ending": "lose_timeout" }] },
  "areas": { "escape": [[50, 50], [53, 53]] },
  "events": [
    { "on": "start", "do": [{ "say": "王進", "line": "pab:N01#0" }, "…"] },
    { "on": { "turn": 1, "phase": "player" }, "do": [{ "spawn": "hero" }, { "say": "都頭", "line": "pab:N01#5" }] },
    { "on": { "enter": "ambush1", "side": "player" }, "do": [{ "ai": { "group": 512, "mode": "冲锋" } }] }
  ]
}
```

- 对白通过 `pab:关卡#序号` 引用原文。文本不复制进事件文件，原文由运行时解析器读取。
- 触发：回合开始、单位进入区域、单位倒下、单位生命低于某值、对话结束。
- 动作：对白、出场/增援、移动、改 AI、加入队伍、给道具、设胜负、结局。
- 剧情关（`Act*`）也用同一格式，只是没有胜负条件。

### 9.3 编写顺序

先写第 1–2 章（关卡 0–10）的事件脚本，作为竖切片；其余章节在规则稳定后批量编写。每章需要你提供一段游玩录像或关键截图，用来核对出场时机和撤退区域。

## 12. 技术架构

### 12.1 模块划分

```
src/
  formats/     原版格式解析（已有：exe、goo、hum、act、map、pas、image），浏览器与 Node 共用
  data/        把解析结果整理成游戏数据：Character、ClassDef、Item、Skill、StageDef
  rules/       纯 TypeScript 规则引擎：棋盘、寻路、行动、战斗计算、AI、事件执行（不依赖 Phaser，可单测）
  game/        Phaser 4 场景与表现层
    scenes/    Boot、Setup（选原版目录）、Title、Story、Battle、Camp、Settings
    view/      等距地图渲染、单位精灵、特效、UI 组件
  content/     手写内容：事件脚本、地形修正、技能模板映射、AI 指定、头像对照、平衡数值
tools/         Node 工具（已有：gen-design-docs、render-maps）
```

### 12.2 关键设计

- **自带原版文件**：首次启动用 File System Access API（或 `<input webkitdirectory>` 兜底）选择目录。图像库解码成纹理图集，存进 IndexedDB；以后启动直接读缓存。原版文件只在玩家本机。
- **规则与表现分离**：`rules/` 输出"事件流"（移动了、命中了、伤害多少），`game/` 只负责播放。这样可以做快进、跳过、自动测试和数值模拟。
- **确定性随机**：使用带种子的随机数，存档记录种子。读档后结果一致，避免反复读档刷结果（可设置关闭）。
- **存档**：JSON 存在 IndexedDB，可导出、导入为文件。
- **测试**：格式解析器对原版数据做回读测试；规则引擎单测；关卡事件脚本做"无头自动对战"冒烟测试。

## 14. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| PAS 事件指令解不开 | 胜负判定、增援时机只能靠人工还原 | 事件脚本人工编写；用游玩录像核对；逆向作为辅助 |
