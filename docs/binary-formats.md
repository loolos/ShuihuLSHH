# 原版文件格式（binary-formats）

> 实现时查格式和字段就看这一份。分析方法：只读解析原版文件，并对 `ShuiHu.exe` 做静态反汇编。**没有运行原版 EXE。**解析器在 `src/formats/*.ts`。
> 置信度：**高** = 对该格式的全部文件/全部条目程序化验证通过；**中** = 结构吻合，字段语义由旁证推断；**低** = 假设，需要实验或反汇编确认。
> 下文偏移均为十六进制或十进制字节数，整数均为小端序（little-endian）。

## 1. 自定义格式的共同文件头

大多数自定义格式共用同一套头部风格：3 字节 ASCII 魔数 + 1 字节（`\0` 或版本）+ 1 字节版本号（恒为 `01`）+ u16 条目数 + u32 偏移/长度。

| 魔数（0–3） | +4 | +5 u16 | +7 | 头长 |
|---|---|---|---|---|
| `GRP\0` | `01` | 帧数 | u32 索引表偏移 | 11（后接 128 B 源路径） |
| `PIC\0` | `01` | 帧数 | u32 索引表偏移 | 11 |
| `LIB\0` | `01` | 帧数 | u16 A、u16 B、u32 C（见 §4） | 15 |
| `MAP\0` | `01` | 宽 W | u16 高 H | 9 |
| `ACT\x02` | `01` | 单位数 | u32 头长 = 11 | 11 |
| `GOO\0` | `01` | 记录数 = 200 | u32 头长 = 11 | 11 |
| `HUM\0` | `01` | 记录数 = 72 | u16 基础记录长 = 51，u32 头长 = 13 | 13 |
| `PAS` + u32 | — | — | — | 15（`+3` u32 = 文件长 − 15） |

`ShuiHu.exe` 中有 `GRP`/`grp`/`att`、`GOO`、`HUM`、`ACT`/`act`、`MAP`/`map`、`PAS`/`pab`、`GAM`（存档魔数）等短字符串，与上表一一对应（置信度：高）。

## 2. 图像帧压缩：两种 RLE

每个图像帧在索引里带 1 个编码标志，取值只有 1 和 2。按以下算法解压后，**全部 29,191 帧**的输出长度都恰好等于 宽 × 高（置信度：高）。

**编码 1 = PCX 式 RLE**

```
while 未到帧末尾:
    b = 读1字节
    if b >= 0xC0:  n = b & 0x3F; v = 读1字节; 输出 v 重复 n 次
    else:          输出 b
```

**编码 2 = PackBits（Apple/TIFF 式 RLE）**

```
while 未到帧末尾:
    n = 读1字节（视为有符号 int8）
    if 0 <= n <= 127:    原样复制接下来的 n+1 字节
    elif -127 <= n <= -1: v = 读1字节; 输出 v 重复 1-n 次
    else (n == -128):    跳过
```

两种编码都是 8 位调色板索引，按行优先排列，**无行尾标记**（行宽 = 索引里的宽度）。各库的帧四角像素几乎全为索引 0，推断**索引 0 = 透明色**（置信度：中；`Object.lib` 图标四角多为 13，是不透明的底框）。

## 3. GRP（地图图块库）与 PIC（图像库）

### 3.1 GRP 布局

```
0x00  char[4]  "GRP\0"
0x04  u8       版本 = 1
0x05  u16      帧数 N           (Grid=5, Ground=758, Upper=1018)
0x07  u32      索引表偏移        (= 最后一帧数据末尾)
0x0B  char[128] 制作时的源描述文件路径，如 "def\ground.txt"，其余补 0
0x8B  ...      帧数据（第 0 帧从 0x8B 开始）
索引表：N × 20 B
```

### 3.2 PIC 布局

与 GRP 相同，但**没有** 128 B 路径字段（第 0 帧从 0x0B 开始），且索引项为 19 B（编码标志为 u8）。

### 3.3 索引项

| 偏移 | GRP（20 B） | PIC/LIB（19 B） | 含义 | 置信度 |
|---|---|---|---|---|
| +0 | u32 | u32 | 帧数据在文件中的偏移 | 高 |
| +4 | u16 | u16 | 宽 | 高 |
| +6 | u16 | u16 | 宽的副本（全部样本都等于 +4，推测为行跨度 pitch） | 中 |
| +8 | u16 | u16 | 高 | 高 |
| +10 | u16 | u16 | 锚点 X | 中 |
| +12 | u16 | u16 | 锚点 Y | 中 |
| +14 | u16 | u8 | 编码：1 = PCX-RLE，2 = PackBits | 高 |
| +16 / +15 | u32 | u32 | 压缩后字节数 | 高 |

锚点证据：地表块统一为 90×46、锚点 (45, 23)，正好是菱形中心；地上物（树、房屋）锚点 Y 接近图像底部（如 84×84 → (44, 73)），符合"脚底对齐格子中心"的等距视角绘制方式。

### 3.4 内容

| 文件 | 帧数 | 编码 1/2 | 典型尺寸 | 内容（目视） |
|---|---:|---|---|---|
| `Grid.grp` | 5 | 4/1 | 90×46 | 绿色菱形格光标、选择框 |
| `Ground.grp` | 758 | 571/187 | 90×46（743 帧） | 等距地表菱形块（泥土、草地、裂地等） |
| `Upper.grp` | 1018 | 479/539 | 各异 | 地上物：树木、岩石、建筑件 |
| `Head.lib`（PIC） | 79 | 16/63 | 140×≈190 | 角色半身头像 |
| `Object.lib`（PIC） | 200 | 105/95 | 27×27 | 200 件道具的图标（与 `Goods.dab` 200 条对应） |

## 4. LIB（动画帧库）

### 4.1 布局

```
0x00  char[4] "LIB\0"
0x04  u8      版本 = 1
0x05  u16     帧数 N
0x07  u16     A          ┐ 动作组表条数 = A + B（三个文件均成立）
0x09  u16     B          ┘
0x0B  u32     C          （Effect.lib 中 C = 动作组表偏移；Man/Panel 中含义不明）
0x0F  ...     帧数据
...   动作组表：(A+B) × 8 B
EOF-19N  索引表：N × 19 B（结构同 §3.3）
```

| 文件 | N | A | B | 组表条数 | 编码 1/2 | 最大帧尺寸 |
|---|---:|---:|---:|---:|---|---|
| `Man.lib` | 26,021 | 1,620 | 72 | 1,692 | 1,033/24,988 | 186×189 |
| `Effect.lib` | 998 | 60 | 0 | 60 | 607/391 | — |
| `Panel.lib` | 112 | 73 | 34 | 107 | 29/83 | 640×480 |

### 4.2 动作组表

每项 8 B：`u16 first, u16 last, u16 count, u16 param`，全部条目满足 `count = last − first + 1`（置信度：高）。

- **`Man.lib`**：前 B = 72 项的 first/last 是**组号**范围（0–39、40–67…，合计覆盖 0–1619 共 1620 组），后 A = 1620 项的 first/last 是**帧号**范围（0–26020，连续无缺）。72 恰好等于 `Human.hum` 的职业数，因此推断为"职业 → 动作组范围 → 帧范围"的两级索引（置信度：中）。
  - 每个职业的组数都是 4 的倍数，且相邻 4 组帧数相同 → 推断每个动作含 **4 个朝向**（置信度：中）。例：职业 0（武龍）有 40 组 = 10 个动作 × 4 方向。
  - `param` 是动作类型：1 = 走路（动作 0），2 = 受击（动作 1），3 = 防御（动作 2，只有 1 帧），0 = 攻击和技能（动作 3 起，每个技能一组；士兵的动作 3 是普通攻击）。负责人看图确认（2026-11-11，武龍和士兵）；技能动作与技能表的对应顺序待逐个核对（中）。原版没有单独的站立动作，站立时用走路的第 1 帧。
- **`Effect.lib`**：60 组连续覆盖 998 帧，`param` 全为 4（推测为帧间隔或播放速度，低）。最后 8 组各 1 帧。
- **`Panel.lib`**：107 组；包含 4 帧一组的按钮/图标状态、640×480 的全屏背景（标题画面等）。A/B 两段各自对应什么界面待确认。

## 5. MAP（战场地图）

```
0x00  char[4] "MAP\0"
0x04  u8      版本 = 1
0x05  u16     宽 W（格）
0x07  u16     高 H（格）
0x09  W×H 个格子，依次排列；每个格子是一条图层链：
        重复 { u16 tile; u8 cont; u16 flags }   // 5 B
        cont = 0 → 本格结束；cont = 2 → 后面还有一层
```

验证（置信度：高）：63 张图全部恰好解析到文件末尾（剩余 0 字节），`cont` 只出现 0 和 2。

| 观察 | 数据 | 推断 | 置信度 |
|---|---|---|---|
| 尺寸 | 18×18、36×36、54×54，`N03` 为 36×54 | 地图以 18 格为单位拼接 | 高 |
| 每格层数 | 1–5 层 | 第 1 层 = 地表，其余 = 地上物 | 中 |
| 第 1 层最大编号 | 757 | `Ground.grp` 共 758 帧（0–757），恰好吻合 | 高 |
| 后续层最大编号 | 1017 | `Upper.grp` 共 1018 帧（0–1017），恰好吻合 | 高 |
| flags | 0、0x40、0x80、0xC0 | 两个独立位；推测为水平/垂直镜像或绘制顺序标志 | 低 |
| 行列顺序 | — | 假设为行优先、等距视角下的菱形坐标；需渲染整图核对 | 低 |

`Ground.grp` 的块是 90×46 的菱形，因此地图是**等距（isometric）菱形格**；格子在屏幕上的步进（推测为 X ±45、Y ±23）尚待整图拼接验证。

## 6. ATT（图块属性）

```
0x00  char[4] "GPIF"（Ground.att） / "GOIF"（Upper.att）
0x04  u32     条目数 = 2048
0x08  u8[2048] 每个图块编号一个字节，取值只有 0x00 和 0xFF
```

## 8. PAS（剧本与事件脚本）

```
0x00 "PAS"
0x03 u32  正文长度（= 文件长 − 15，63/63 成立）
0x07 u16  区块数
0x09 u16  城镇号 1–13（只有 13 个文件非 0；与 GOO +146/+172 的城镇号吻合）
0x0B u32  未知
0x0F 区块 × 区块数
```

63 个文件中，区块长度之和都恰好等于文件长度（高）。

**区块**：u16 长度，再加 9 个 u16 头字 w0..w8。

- w0 = 1 为普通区块；4 或 5 为区域触发。
- w8 为触发类型：

| 类型 | 触发 | 参数 | 置信度 |
|---|---|---|---|
| 0 | 第 N 回合；0 = 开战时 | 回合数。N01 区块 1 = 2，即第 3 回合武龍登场 | 高 |
| 1 | 某单位死亡 | 角色号，1000 = 主角 | 高 |
| 4 | 某单位进入区域 | 后接可变长条件，编码未解 | 中 |

- 类型 0 和 1 的区块，头字之后是 `FF FF FF FF` 加一个 u16 参数；指令从区块偏移 26 开始。

**指令**：u16 长度、u16 操作码。操作码 < 24 时，后面还有一个 u16 标志。最后是长度所指的载荷。全部 285 个普通区块（w0 = 1）都能用这条规则完整切分。

| 操作码 | 含义 | 置信度 |
|---|---|---|
| 12 | 选定人物。标志 1 = 角色号；标志 0 = 1000 + ACT 单位序号（所以说话者会有 1001–1008） | 中 |
| 13 | 说话，载荷为 Big5 字符串 | 高 |
| 14 / 15 | 目标 x / y | 中 |
| 16 | 多为 0（朝向？） | 低 |
| 17 | 动作位标志（1, 2, 4, 8, 12, 24） | 低 |
| 18 | 0/1 | 低 |
| 19 | 唯一编号 5–44（剧情旗标？） | 低 |
| 20 / 21 | 播放音效，如 "m08" | 中 |
| 27 | 罕见 | 低 |
| 28 | 结束（长度 0） | 高 |
| 29 / 30 | 旁白 / 结局文字 | 高 |
| 31 / 32 / 33 | 回合限制 / 胜利条件 / 失败条件文字 | 高 |
| 35 | 回合限制（2 字节） | 高 |

- 63 个 `.pab` 共有 853 句对白，全部能提取。字符串中的 `%X` 是主角名。
- `.pas` 是同一脚本的 GB2312 转码版本，程序只读 `.pab`。
- 当前 `src/formats/pas.ts` 还只按对白模式提取，尚未使用上面的区块解析。

## 12. 其它格式

- **`Default.pal`**：768 B = 256 × (R, G, B)，每通道 0–255（不是 VGA 的 0–63）。索引 0 = 黑 (0,0,0)。（高）
- **`Default.tbl`**：65,536 B = 256 × 256 u8，满足 `tbl[a][b] = tbl[b][a]`，推断为两种调色板颜色混合（半透明/阴影）后的查找表。与 50% 平均色的平均偏差约 34/255，混合公式未定。（结构高，公式低）
- **`Stdfont.16f` / `Stdfont.24f`**：13,973 字 × 32 B（16×16，1bpp，每行 2 字节，高位在左）/ × 72 B（24×24）。字序 = Big5 码位 `(hi − 0xA1) × 157 + (lo < 0x7F ? lo − 0x40 : lo − 0xA1 + 63)`。（高）
- **`Title\*.flc`**：标准 FLC，ffmpeg 可直接解码。（高）
- **`Sound\*.wav`**：标准 PCM；226 个为 22,050 Hz/16 bit/立体声，其余为 11,025/22,050/44,100 Hz 的单声道或 8 bit。（高）
- **`music.ini`**：141 行 `编号=值`，值 2–24 或空；推测为"场景/事件 → CD 音轨号"（低）。
- **`game.ini`**：`SCROLLSPEED/SOUND/MIDI/VOICE/VIEWENEMY/SAVE`，与 EXE 中的键名字符串一致。
