## 3. 设计路线图

按"先定框架、再填内容"的顺序。每一步都标出依赖和需要你决定的地方。

| 步骤 | 文档 | 内容 | 依赖 | 需要你 |
|---|---|---|---|---|
| D1 | `core-loop.md` 核心循环 | 章节流程：剧情 → 整备（装备、商店、出场）→ 战斗 → 结算 → 下一关；存档点；`Act*` 过场如何呈现 | 关卡简报 | 确认流程，以及出场人数规则 |
| D2 | `combat-rules.md` 战斗规则 | 回合顺序、移动与地形、攻击/反击、伤害与命中公式、必杀、状态异常、经验与升级。原版数值作为参考，**新设计**的部分明确标注 | 规则数据表 | 偏好：简单透明，还是保留原版"属性多、随机性大"的手感 |
| D3 | `skills.md` 技能设计 | 18 名好汉的技能按类型（普通、远程、防御、连续、回旋、气功、集气、回复）重新定数值、范围和消耗 | D2 | 每人技能数量是否精简 |
| D4 | `enemy-ai.md` 敌方 AI | 几种行为模式（冲锋、固守、护卫、撤退、追击特定目标），每关用哪种 | D2、关卡简报 | — |
| D5 | `events.md` 关卡事件 | 把每关的剧情触发写成重制版的事件脚本格式（出场、对白、增援、胜负判定）。先做第 1 章 | 剧本文本、游玩录像 | 第 1 章的游玩录像或截图 |

## 4. 需要游玩核对的问题

以下内容无法只靠文件确定。你在虚拟机里玩到相应位置时，截图或录像即可：

1. 第 1 章 N01 开局和撤退区域的位置，用来核对地图渲染方向和"撤退区域"在哪里。
2. 任意一张 `Act*` 关卡：确认是纯剧情过场，还是有战斗。
3. 一次普通攻击和一次技能的伤害数字，以及双方当时的属性面板。
4. 升级时的属性变化，用来核对成长等级字母 f/g/h/i/j/n。
5. 每关开战前是否能选择出场人员。
