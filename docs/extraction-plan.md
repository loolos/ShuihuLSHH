## 1. ChillWhiteDid/Shuihu-Editor 可复用性评估

仓库：<https://github.com/ChillWhiteDid/Shuihu-Editor>（本次查看的提交 `e4ab5bb`，2026-11-10；MIT 许可，仅覆盖其原创代码）。

**它是什么**：一个 Win32/C 的**存档编辑器**。构建时用 `tools/gen_data.py` 从 `ShuiHu.org`（原版 EXE）、`Data\GOODS.DAB`、`Data\HUMAN.HUM` 提取名字表，编进程序；运行时只读写 `.sav` 存档。它**不涉及**图像、地图、剧本、音频。其 README 引用的《ShuiHu-分析报告.md》v1.41 与《开发说明.md》**不在公开仓库中**。

| Editor 的成果 | 我们的核对 | 可复用程度 | 说明 |
|---|---|---|---|
| EXE 角色名表 VA 0x443A5C（40 项）、技能名表 VA 0x443BC4（256 项） | 用自写读取器在本副本 `ShuiHu.exe` 上读出：武龍…教頭 40 项、一鳴驚人…普通攻擊等技能名 + 章节名，全部正确 | **直接复用（地址与读取规则）** | 本副本没有 `ShuiHu.org`，但 `ShuiHu.exe` 的这两张表与其一致 |
| `GOODS.DAB`：11 B 头 + 200 × 198 B；+0 类型码、+1 大类、+6 名称、+104 移动加成 | 大小、名称、类型码全部吻合 | **直接复用** | 我们在此基础上补充了 +26 说明、+2/+4 图标号、+142/+144 价格等观察 |
| `HUMAN.HUM`：13 B 头 + 72 × (51 B + n × 58 B)；+45 子项数、+9 基础移动；子项 +0 技能 id、+5 隐藏、+17 学习等级 | 72 条恰好消耗整个文件 | **直接复用** | 成长率等其余字段仍需自己解 |
| 存档格式：`GAM\x02`、金钱 @0x1B、锚点扫描、单位字段偏移、7 槽、隐藏技块 | 本副本无存档，无法复核 | **作为参考**（导入旧存档时有用） | 重制版不需要兼容原存档，优先级低 |
| 数值上限：等级 30、属性 255、生命/气力 510；移动 = 职业 +9 + 持久加成 + 装备 +104 合计 | 无法在不运行 EXE 的前提下复核 | **作为规则候选**，标为"待验证" | 来自 Editor 的反编译与游戏内实测 |
| 隐藏技：每职业 3 段（LV1–3），消耗"古武術祕笈"领悟 | 与 EXE 技能名中的"古武術LV1–3"一致 | **作为规则候选** | |
| C 源码（`save.c`、`goods.c`、`human.c`） | — | **不直接复用代码** | 平台（Win98/TCC）与目标（浏览器/TypeScript）不同；按格式说明用 TS 重写即可 |
| `tools/gen_data.py` | 本次**没有执行**它（外部代码），只按其公开的偏移自写了读取器 | 参考实现 | |

**结论**：Editor 能直接省掉"道具表、职业技能表、EXE 名称表"三块的逆向工作，是可靠的交叉验证来源；但对本项目最关键的图像、地图、剧本、动画四块，它没有任何成果，需要我们自己做（本阶段已完成结构解析）。

## 3. 版权与仓库约束（贯穿下一阶段）

- 原版文件与**从中提取的任何产物**（PNG、JSON 文本表、音频）都**不进 GitHub**。仓库只放：提取工具源码、格式文档、手写的规则/配置。
- 建议在开始写工具前先加 `.gitignore`，至少包含：`/original/`、`/extracted/`、`*.lib`、`*.grp`、`*.map`、`*.act`、`*.pab`、`*.pas`、`*.dab`、`*.hum`、`*.wav`、`*.flc`、`*.exe`。
- 提取工具通过环境变量（如 `SHUIHU_DATA`）或命令行参数接收原版目录，**只读**打开；输出写到仓库外或被忽略的 `extracted/` 目录。
- 不运行原版 EXE。需要"游戏内行为"证据时，由用户在自己的环境（虚拟机/实机）手动游玩并截图记录，或使用静态反汇编（只读）。

## 4. 下一阶段：数据提取方案

### 4.1 技术选型

- **提取工具用 TypeScript（Node 20+）**，与 Phaser 4 + TypeScript 运行时共用一套格式类型定义（`src/formats/*.ts`），避免两套实现漂移。本阶段的 Python 原型脚本可作为对照参考。
- 依赖尽量少：PNG 编码用 `pngjs` 或 `sharp`；图集打包用 `free-tex-packer-core` 或自写的 MaxRects；音频转码调用系统 `ffmpeg`。
- 每个解析器都配"回读校验"：解压长度 = 宽×高、索引覆盖整个文件、未知字节保留原样（便于日后重新解释）。

### 4.2 产物格式（面向 Phaser 4）

| 原版 | 产物 | Phaser 用法 |
|---|---|---|
| `Man.lib` | 每职业一张（或按动作拆分）纹理图集 PNG + Phaser Atlas JSON（帧名 `cls{NN}/grp{NNNN}/f{NN}`，含锚点 → `pivot`）+ 动画定义 JSON（组 → 帧列表、方向、推测动作名） | `this.load.atlas` + `this.anims.create` |
| `Effect.lib` | 图集 + 60 个动画定义 | 同上 |
| `Head.lib`、`Object.lib`、`Panel.lib` | 图集（锚点写入 pivot） | `this.load.atlas` |
| `Ground.grp`、`Upper.grp`、`Grid.grp` | 图集；地表块统一 90×46 | 等距 Tilemap 或自绘 |
| `*.att` | `tile-attrs.json`（ground/upper 各 2048 项） | 寻路阻挡 |
| `Map\*.map` | 每图一个 JSON：`{width, height, cells:[[{tile, flags}, …]]}`，并可另导出 Tiled（`.tmj`，`orientation: isometric`）以便人工查看 | 运行时自绘等距层 |
| `Map\*.act` | `units.json`：坐标、阵营、朝向、职业/道具、等级、7 槽、未解字段原样保留 | 关卡初始化 |
| `Map\*.pab` | `script.json`：已识别指令结构化，未识别指令保留为原始 u16 数组；对白转 UTF-8 繁体（另存简体转换版） | 事件系统 |
| `Goods.dab`、`Human.hum`、EXE 名称表 | `items.json`、`classes.json`、`skills.json`、`characters.json` | 规则数据 |
| `Sound\*.wav` | OGG（Vorbis）+ M4A/MP3 备用 | `this.load.audio` |
| `Title\*.flc` | WebM/MP4（或逐帧 PNG） | 视频对象 |
| `Default.pal` | `palette.json`（调试/调色板特效用） | — |

调色板在提取时直接烘焙进 PNG（索引 0 → 透明）。如果日后发现需要运行时调色板替换（如敌我换色），再改为导出索引图 + 调色板纹理。

### 4.3 里程碑（建议顺序）

| # | 任务 | 完成标准 |
|---|---|---|
| M1 | 搭建工具骨架：只读加载原版目录、`.gitignore`、SHA256 校验（与 file-inventory.md 对表，防止用错版本） | 528 个文件哈希一致 |
| M2 | 通用解码器：GRP/PIC/LIB 索引 + PCX-RLE/PackBits；导出 PNG | 29,191 帧全部导出，长度校验 0 失败 |
| M3 | 地图渲染验证：用 `Ground/Upper` 把 `N01.map` 渲染成整张等距图，确定格子→屏幕坐标、图层绘制顺序、flags 含义 | 与游戏截图（由用户提供）一致 |
| M4 | `Man.lib` 动作标注：为每个职业生成"动作组预览表"，人工标注站立/行走/攻击/受击/施法/倒地；确定 4 个方向的顺序 | 72 职业 × 动作表填完 |
| M5 | 规则数据：`items/classes/skills/characters.json`，并把 Editor 的字段与本项目新发现合并；未知字段原样保留 | JSON 通过 schema 校验 |
| M6 | 关卡数据：`units.json` + 对白抽取；继续解 PAS 指令集（从对白前后的指令入手，对照游戏实际剧情） | 第 1 章全部关卡可在网页中"摆出来"（地图 + 单位 + 对白） |
| M7 | 音频/视频转码与映射表（音效编号用途靠游戏内对照逐步补充） | 全部可在浏览器播放 |
| M8 | 战斗规则研究（见 mechanics-research.md 的待验证清单），形成可实现的规则文档 | 每条规则有证据和置信度 |

### 4.4 需要用户协助的地方

1. **游戏内截图/录像**：地图整图、单位朝向、各动作、战斗数值变化。这是验证 M3/M4/M8 最快的途径，用户在自己机器上游玩即可，Claude 不运行 EXE。
2. **原版光盘音轨**（如果有）：用于确认 BGM 与 `music.ini` 的对应关系；没有的话重制版需要另配音乐。
3. **存档样本**：若希望验证 Editor 的存档结论或做"原版存档导入"，需要几份不同进度的 `.sav`。
4. **繁/简体选择**：原版运行文本是 Big5 繁体，`.pas/.dat` 是简体副本。重制版默认用哪种，或两者都支持。
