# 项目总纲（project-overview）

> 本文是重制项目的主文档：说明目标、还原范围、设计原则、约束和待决问题。格式与数据细节见下方"文档索引"。
> 状态：草案，2026-11-11。凡标"待决"的条目需要项目负责人拍板。

## 1. 目标

用 **Phaser 4 + TypeScript** 在浏览器中重制 1999 年智冠科技 / 红蚂蚁的《水浒传之梁山好汉》，做成一款等距视角的战棋 RPG。

**一句话定位**：**关卡和剧情尽量还原原作，战斗规则可以重新设计。**

## 2. 还原范围

### 2.1 必须还原（以原版数据为准）

这些内容决定"这还是不是那款游戏"，偏离必须有明确理由并记录。

| 内容 | 原版来源 | 现状 |
|---|---|---|
| 章节结构与关卡顺序（14 章、主线图 / 战役图 / 追加图、训练关） | EXE 关卡表（76 项）、`Map\` 文件名 | 已解析 |
| 每关地图布局（地形、建筑、地上物的位置） | `Map\*.map` + `Ground/Upper.grp` | 结构已解析，渲染待验证（M3） |
| 每关敌我单位的初始配置：职业、位置、朝向、阵营、装备 | `Map\*.act` | 已解析大部分字段 |
| 剧情对白：说话者、顺序、文本 | `Map\*.pab` | 对白已可抽取；事件指令未解 |
| 关卡目标与胜负条件 | `.pab` 末尾目标文字 + 事件指令 | **部分未知**，需对照游玩补全 |
| 登场人物阵容：主角武龍 + 17 名可控好汉，以及加入时机 | EXE 角色名表、关卡单位 | 已整理，见 design/game-design.md §1.4 |
| 道具与装备的名称、说明、类别体系（11 类武器、衣服、头饰、消耗品、财宝） | `Goods.dab` | 已解析 |
| 职业↔武器类别的对应、每个职业的技能**名称**与习得顺序 | `Human.hum`、EXE 技能名表 | 已解析 |
| 美术风格：人物 Sprite、头像、地图图块、特效的整体观感 | `*.lib`、`*.grp` | 全部可解码（见 §5 资产来源问题） |

### 2.2 参考原作，但可以调整

以原版数据作为**初始值或参考**，但以"好玩、平衡、易懂"为准，不追求逐数值复刻。所有数值必须写进数据表，不写死在代码里，方便后续调整。

| 内容 | 原则 |
|---|---|
| 伤害、命中、闪避、必杀公式 | 自行设计一套透明、可预测的公式；保留原版的属性名（攻擊、防禦、命中、敏捷、必殺），让属性含义与原版大体一致 |
| 技能数值：威力、范围、气力消耗、特效 | 技能名称和定位（远程、回复、连续技…）按原版，具体数值重新设计 |
| 角色成长：经验公式、升级成长、等级上限 | 参考原版的上限（等级 30、属性 255 等）；成长曲线自行设计 |
| 敌方 AI | 不必复刻原版行为；按关卡需要实现几种模式（冲锋、固守、护卫、逃跑），可以比原版更聪明 |
| 回合顺序、移动规则、地形效果 | 选择一种清晰的规则即可；原版规则未知的地方不必花大量时间去考证 |
| 经济：价格、掉落、商店货品 | 原版价格作为初始值，按新的数值体系调整 |
| 状态异常（中毒、昏迷）的具体效果与持续时间 | 保留种类，效果自行设计 |
| 装备"提升" | 保留"可提升 / 无法提升"的区分，机制自行设计 |

### 2.3 可以自由设计

| 内容 | 说明 |
|---|---|
| UI 与操作 | 现代化布局、鼠标与触控操作、快捷键、提示信息 |
| 便利功能 | 移动撤销、战斗快进、自动存档、敌方攻击范围预览、对白回看 |
| 字体与文字渲染 | 使用网页字体，不使用原版点阵字库 |
| 音乐 | 本副本缺少 CD 音轨，需要另配（见 §5） |
| 存档系统 | 浏览器本地存储，不兼容原版 `.sav` |
| 难度选项 | 可新增 |

## 3. 设计原则

1. **数据驱动**：关卡、单位、对白、道具、技能、数值全部来自 JSON 数据；规则引擎只读数据。这样还原内容（来自提取）和可调内容（手写）可以分开维护。
2. **还原内容可追溯**：每份还原数据都记录原版来源文件和字段；手工修正必须单独记录（如 `overrides/*.json`），不直接改提取结果。
3. **规则与表现分离**：战斗规则是一个与 Phaser 无关的纯 TypeScript 模块，可以单独做单元测试和数值模拟。
4. **证据优先**：在原版文档中，凡涉及原作的结论都要标出证据和置信度；在设计文档中，凡是自行设计、与原作不同的地方要明确写"新设计"。
5. **先竖切片，再铺量**：先把第 1 章做成完整可玩的流程，再扩展到全部 14 章。

## 4. 硬性约束

- 不运行原版 EXE；不修改原版文件。
- 仓库必须保持**私有**。原版文件（不含 `Sound/`、`Title/`）存放在 `gamedata/shuihu/`，供开发读取，不得修改（2026-11-11 用户决定）。提取产物（PNG、JSON、音频）仍不入库。
- 提取工具以只读方式读取原版目录，产物写到被忽略的 `extracted/` 目录。
- 需要游戏内行为作证据时，由负责人在自己的环境中游玩并截图，或对 EXE 做只读静态分析。

## 5. 待决问题

按对项目的影响排序。§5.1 的三项已决定；其余待定。

### 5.1 资产与发布（已决定，2026-11-11）

1. **发布形态** → **主要自用**，可以使用原版素材。
2. **素材使用方式** → **自带原版文件**：玩家在浏览器中选择自己的原版目录，素材在本地实时解码，仓库和服务器都不分发素材（类似 ScummVM、OpenRA 的做法）。
   影响：
   - 解码器（GRP/PIC/LIB、MAP、ACT、PAS、GOO、HUM）必须能在浏览器中运行，并与离线提取工具共用同一套 `src/formats/*.ts`。
   - 首次启动时需要有"选择原版目录"流程（File System Access API，或用 `<input webkitdirectory>` 兜底），并做文件校验（对照 file-inventory.md 的 SHA256）。
   - 解码结果缓存到 IndexedDB，避免每次启动都重新解码。
   - 离线提取工具保留，用于开发调试和生成预览，产物仍不入库。
3. **画面规格** → **自适应浏览器窗口**，不固定像素。
   影响：
   - 画布随窗口缩放，UI 按屏幕尺寸布局，不照搬原版 640×480 的面板位置。
   - 原版图块和 Sprite 是低分辨率像素图，需要选定缩放策略（整数倍最近邻，或非整数倍时的平滑处理）。
   - 地图视野随窗口大小变化，可见格数不固定。

### 5.2 剧情与文本

4. **繁体还是简体**：默认显示哪种？是否两者都支持？
5. **对白处理**：逐句保留原文，还是允许修正错字、润色？
6. **主角改名**：是否保留可改名（对白中的 `%X` 占位符）？
7. **剧情缺口**：PAS 事件指令（出场、移动、分支、胜负判定）还没解开。可以继续逆向，也可以根据游玩录像手工重写每关的事件脚本。建议后者为主、前者为辅。
8. **分支与结局**：原作是否有剧情分支、多结局，或可选关卡（如 `N-add*` 追加图）？需要确认。
9. **片头与过场**：缺少 tiger/tail AVI，是用现有 FLC Logo 代替，还是另做片头？

### 5.3 玩法

10. **出场选择**：每关能否自选出场好汉，人数上限是多少？没有原版证据时采用哪种？
11. **战斗演出**：攻击时是否切到原版那样的战斗动画画面（原版是否有需确认），还是在地图上直接演出？是否可以跳过？
12. **新内容**：是否加入原作没有的内容（新关卡、新技能、新角色）？还是严格限定在原作范围内？
13. **难度基准**：以"原版难度体感"为目标，还是重新定位（更简单或更难）？
14. **永久死亡**：好汉倒下后是退场还是下关复活（原版规则需确认）？

### 5.4 音频

15. **音乐**：本副本没有 CD 音轨。是找原版光盘提取（仅供私用），还是另配新音乐？场景切换规则可以沿用 `music.ini`。
16. **语音与音效**：`Sound\` 里的 245 个 WAV 是否沿用？这和第 2 项同样受版权约束。

### 5.5 平台与工程

17. **目标平台**：只做桌面浏览器，还是也支持手机和平板（触控、竖屏）？
18. **存档**：只用本地存储，还是要求云同步或导出存档文件？
19. **第一个可玩里程碑**：建议以"第 1 章全部关卡可玩"作为竖切片的完成标准，确认是否同意。
